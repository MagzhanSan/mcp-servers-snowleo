# Инструкция для владельца: как подать наши MCP-серверы в каталоги

Читай сверху вниз и делай ровно то, что написано. Ничего додумывать не надо.
Всё, что здесь есть, делается в браузере, кроме одного шага с терминалом.

**Сколько это займёт:** 20 минут на подготовку (шаги 1–3), дальше по 5–15 минут
на каталог.

---

## Сначала главное: это ставка, а не проверенный канал

У нас **нет ни одного замера**, что каталоги MCP-серверов приводят покупателей.
Ни одного. Мы идём туда по одной причине: в самом магазине Apify место в выдаче
считается по числу уникальных пользователей (поле `storePosition`), мы сидим на
48–66 тысячах из 70 тысяч, и в людной нише нас не видно вовсе. В каталогах MCP
такой стены нет, серверов там тысячи, а не семьдесят тысяч.

Это довод, а не доказательство. Возможно, канал окажется пустым.

**Условие смерти канала.** Через **две недели** после того, как последний листинг
станет виден публично, открой Apify Console → каждый актёр → вкладку с
аналитикой и посмотри число уникальных пользователей. Если **ни у одного из 21
актёра** не прибавилось ни одного чужого уникального пользователя (своего
тестового не считаем) — канал пустой, мы его закрываем и больше на него времени
не тратим. Дату проверки поставь в календарь прямо сейчас, до первой подачи.

## Шаг 1. Выложить репозиторий на GitHub (10 минут)

Почти каждый каталог требует ссылку на репозиторий. Поэтому это первый шаг, а
не последний.

Папка уже собрана и закоммичена у тебя на рабочем столе:
`~/Desktop/mcp-servers-snowleo`. Отправлять её никуда я не стал — это делаешь ты.

1. Зайди на https://github.com под своим логином. Если аккаунта нет — заведи,
   это бесплатно, нужен только email.
2. Нажми **New repository** (зелёная кнопка справа сверху, или
   https://github.com/new).
3. Заполни:
   * **Repository name:** `mcp-servers-snowleo`
   * **Description:** `MCP servers exposing Snow Leo Data web-data tools`
   * Выбери **Public**.
   * **НЕ** ставь галочки «Add a README file», «Add .gitignore», «Choose a
     license» — они уже есть в папке, и галочки создадут конфликт.
4. Нажми **Create repository**.
5. Открой Терминал и выполни по одной строке, подставив свой логин GitHub
   вместо `ТВОЙ-ЛОГИН`:

```bash
cd ~/Desktop/mcp-servers-snowleo
git remote add origin https://github.com/ТВОЙ-ЛОГИН/mcp-servers-snowleo.git
git push -u origin main
```

   Если GitHub спросит пароль — обычный пароль не подойдёт, нужен токен:
   https://github.com/settings/tokens → **Generate new token (classic)** →
   галочка `repo` → скопировать и вставить вместо пароля.

6. Открой https://github.com/ТВОЙ-ЛОГИН/mcp-servers-snowleo и убедись, что
   README виден. **Запиши эту ссылку — она понадобится в каждой форме.**

## Шаг 2. Проверить, что серверы действительно работают (3 минуты)

Прежде чем подавать, убедись своими глазами, что подключение живое. Иначе
каталог отклонит заявку, а мы не поймём почему.

1. Открой Claude Desktop → Настройки (`Ctrl+,` или меню → File → Settings).
2. Слева выбери **Connectors** → кнопка **Add** → **Add custom connector**.
3. Вставь адрес самого короткого сервера:

```
https://mcp.apify.com/?actors=snow_leo_data/google-news-scraper,snow_leo_data/telegram-channel-scraper
```

4. Нажми **Add**. Тебя перебросит на Apify — войди своим аккаунтом и разреши.
5. В настройках коннектора должны появиться инструменты. Если появились —
   всё работает, можно подавать. Коннектор после проверки можно оставить.

Это единственная проверка. Прогонять актёры в облаке не надо — у нас на счету
$3.5 из $9.

## Шаг 3. Официальный реестр MCP (15 минут) — делать ПЕРВЫМ из каталогов

**Да, нам туда можно.** Я проверил это тремя способами, ответ ниже в разделе
«Можно ли нам в официальный реестр». Реестр бесплатный, ручного ревью нет,
публикация происходит мгновенно, и несколько других каталогов забирают данные
именно оттуда — поэтому это первый каталог, а не последний.

1. Установи публикатор. В Терминале:

```bash
brew install mcp-publisher
mcp-publisher --help
```

   Если `brew` не установлен — поставь его с https://brew.sh (одна команда с
   их главной страницы).

2. Подставь свой логин GitHub в файлы. Одной командой, вместо `ТВОЙ-ЛОГИН`
   поставь свой логин:

```bash
cd ~/Desktop/mcp-servers-snowleo
./set-github-user.sh ТВОЙ-ЛОГИН
git add -A && git commit -m "chore: set GitHub namespace" && git push
```

3. Войди в реестр (откроется браузер, вход через GitHub):

```bash
mcp-publisher login github
```

4. Опубликуй пять серверов, по одному. Выполняй строки по очереди:

```bash
cd ~/Desktop/mcp-servers-snowleo/leads        && mcp-publisher publish
cd ~/Desktop/mcp-servers-snowleo/jobs         && mcp-publisher publish
cd ~/Desktop/mcp-servers-snowleo/marketplaces && mcp-publisher publish
cd ~/Desktop/mcp-servers-snowleo/risk         && mcp-publisher publish
cd ~/Desktop/mcp-servers-snowleo/media        && mcp-publisher publish
```

5. Проверь, что они там (вместо `ТВОЙ-ЛОГИН` — свой логин):

```bash
curl -s "https://registry.modelcontextprotocol.io/v0/servers?search=snowleo" | head -c 800
```

**Риск, о котором надо знать заранее.** В правилах реестра (Условия §9.4 и
политика модерации) написано, что они удаляют «один и тот же сервер, поданный
несколько раз под разными именами». Наши пять — это пять разных наборов
инструментов на одном шлюзе, а не один и тот же сервер пять раз, и формально
правило мы не нарушаем. Но если ты хочешь перестраховаться: опубликуй сначала
**два** — `leads` и `jobs`, подожди три дня, посмотри, что их не сняли, и только
потом остальные три. Модерация там реактивная, наказание — статус `deleted`,
не блокировка аккаунта.

## Шаг 4. Smithery (10 минут)

1. Открой https://smithery.ai/new — попросит войти (через их вход WorkOS,
   можно GitHub-аккаунтом).
2. Выбери способ **URL** («bring your own hosting»), не локальный бандл.
3. Вставь адрес сервера. Начни с одного — `media`, он самый короткий:

```
https://mcp.apify.com/?actors=snow_leo_data/google-news-scraper,snow_leo_data/telegram-channel-scraper
```

4. Пройди шаги публикации до конца. Smithery сам сходит на адрес и попробует
   вычитать список инструментов.

**Честно о том, что может пойти не так.** Наш сервер закрыт авторизацией
(без токена он отвечает 401). Smithery заявляет поддержку OAuth, но если их
робот не сможет войти и прочитать инструменты, листинг не соберётся. Запасной
путь у них — положить файл `/.well-known/mcp/server-card.json` на свой домен,
а домен `mcp.apify.com` не наш, положить туда мы ничего не можем. **Если скан
не прошёл — не бейся, просто пропусти Smithery и иди дальше.** Это не наша
ошибка и не чинится с нашей стороны.

Бесплатный тариф Hobby: 50 000 вызовов в месяц, платить не надо.

## Шаг 5. mcpservers.org (15 минут) — самая простая форма

https://mcpservers.org/submit

Листинг бесплатный, ревью до двух недель. Есть платный вариант за $39 с ревью
за сутки — **не бери его**.

Заполни форму пять раз, по одному разу на сервер. Что вводить:

* **Server Name** — название сервера (колонка «Название» в таблице ниже).
* **Category** — выбери из списка то, что ближе всего; точного совпадения может
  не быть, это нормально.
* **Short Description** — колонка «Описание» ниже, скопируй как есть.
* **Repository, Website or Documentation** — ссылка на папку сервера в нашем
  репозитории, например
  `https://github.com/ТВОЙ-ЛОГИН/mcp-servers-snowleo/tree/main/leads`
* **Official MCP Registry Name** — необязательное поле, но заполни: там мы уже
  есть после шага 3. Значение — `io.github.ТВОЙ-ЛОГИН/snowleo-leads` и так далее.
* **«This server supports remote connections»** — **обязательно поставь галочку.**
* **Contact Email** — твоя почта.

| Название | Описание (скопировать целиком) |
|---|---|
| Snow Leo Leads & Contacts | Local business leads from Google Maps, 7 directories, DuckDuckGo and OpenStreetMap, with contacts |
| Snow Leo Jobs & Hiring | Live job listings from 20 ATS platforms plus SEEK, JobStreet, JobsDB, jobs.ch and The Muse |
| Snow Leo Marketplaces & Prices | Priced listings from Amazon, Shopify stores, the App Store, Google Play, Airbnb and Redfin |
| Snow Leo Risk & Compliance | Screen names against OFAC, EU and UN lists; check CVEs, domain DNS and WHOIS, and public tenders |
| Snow Leo News & Social | Read Google News across 80 editions and any public Telegram channel, without an API key |

Адреса серверов, если форма их спросит, лежат в `README.md` в корне репозитория,
в разделе каждого сервера — там же их можно скопировать.

## Шаг 6. mcpmarket.com (10 минут)

https://mcpmarket.com/submit

1. Вкладка **MCP Server**, переключатель — **Remote MCP** (не «GitHub repo»).
2. URL — адрес сервера, email — твой.
3. Внизу выбери **Free Queue — $0**. Там же предложат «Get Listed Now» за $29 —
   **не бери**.

Бесплатная очередь: листинг в среднем через 4–6 недель. Это самый долгий
каталог в списке, поэтому подавай сюда раньше, а не позже.

## Шаг 7. Glama (10 минут) — ТОЛЬКО ЕСЛИ СОГЛАСЕН ОТДАТЬ ТОКЕН

https://glama.ai/mcp/connectors → кнопка **Add Server** в панели сверху
(войти через GitHub).

**Прочитай это до того, как нажмёшь.** Glama индексирует удалённые серверы так:
подключается к адресу как обычный MCP-клиент и вычитывает инструменты. Чтобы
это сработало на закрытом сервере, у тебя попросят учётные данные — то есть
**токен Apify**. Токен Apify даёт полный доступ к аккаунту: чужой человек с ним
может запускать актёров, за которые заплатим мы.

Если решаешь идти:

1. Заведи **отдельный новый токен** в https://console.apify.com/account/integrations
   (не тот, которым пользуешься сам).
2. Отдай его Glama.
3. Как только сервер проиндексировался — **сразу удали этот токен** в той же
   консоли. Листинг уже собран, токен больше не нужен.

Если не согласен — пропусти шаг 7 **и шаг 8**: восьмой без седьмого не работает.

## Шаг 8. awesome-remote-mcp-servers (20 минут) — требует шага 7

https://github.com/punkpeye/awesome-remote-mcp-servers — список на GitHub
на 248 звёзд, специально для удалённых серверов. Подача — Pull Request.

**Обязательное условие:** сервер уже должен быть в каталоге коннекторов Glama,
потому что в записи обязателен бейдж Glama. Без него PR не примут. Поэтому шаг 8
идёт после шага 7, а не вместо него.

Формат записи — ровно три строки, аккуратно скопируй структуру из соседних
записей в их `README.md`. Авторизация у нас OAuth, значит маркер — 🔐. Описание
не длиннее 120 знаков и с точкой в конце.

Их CI на каждый PR сам стучится на адрес и проверяет, что сервер отвечает на
`initialize`. Наш отвечает — я проверил, все пять адресов дают 401 без токена,
а это ожидаемый ответ закрытого сервера, а не поломка. Если CI всё же
покраснеет из-за авторизации — не спорь, закрой PR и иди дальше.

## Чего делать НЕ надо

* **Не плати ни одному каталогу.** Нигде: ни $39 на mcp.so, ни $39 на
  mcpservers.org, ни $29 на mcpmarket. Канал не проверен, платить за
  непроверенный канал нельзя.
* **Не заводи новых аккаунтов Apify** и не создавай второй аккаунт «для
  каталогов». Покупатель платит СВОИМ аккаунтом — в этом весь смысл.
* **Не запускай актёров в облаке Apify для проверки.** На счету $3.5 из $9.
  Проверка из шага 2 ничего не стоит.
* **Не подавай один и тот же сервер в один каталог дважды.** Если сомневаешься,
  прошла ли заявка — поищи её в каталоге, а не подавай заново.
* **Не меняй адреса серверов руками.** Один лишний пробел или запятая — и шлюз
  отдаст не тот набор инструментов. Копируй адреса только из `README.md`.
* **Не отдавай свой основной токен Apify** ни одному каталогу. Только отдельный,
  и сразу удали после индексации (шаг 7).
* **Не переписывай числа в README.** Всё, что там написано, замерено; если
  число перестанет быть правдой, его надо перезамерить, а не подправить.

## Можно ли нам в официальный реестр: да

Вопрос был такой: пустит ли официальный реестр наш удалённый сервер, если домен
`mcp.apify.com` нам не принадлежит.

**Пустит.** Раньше такая проверка была, и её специально убрали.

* В коде реестра осталась одна проверка адреса — `IsValidRemoteURL`
  (`internal/validators/utils.go`): адрес должен быть корректным, по `https`,
  и не на `localhost`. Про домен и пространство имён там нет ни слова.
* Проверку убрали сознательно: задача
  `modelcontextprotocol/registry#494` — «убрать привязку `Remote.url` к имени»,
  и PR `#769` «Remove namespace match validation for websiteUrl and remote URL»
  влит 17 ноября 2025, минус 107 строк.
* В их же документации пример: сервер называется
  `io.github.username/email-integration-mcp`, а адрес удалённого сервера —
  `https://email.example.com/mcp`, то есть чужой домен.
* Живая проверка 17.09: все пять наших файлов отправлены на
  `POST https://registry.modelcontextprotocol.io/v0/validate` и все пять вернули
  `{"valid":true,"issues":[]}`.

**Пространство имён для нас — `io.github.<твой-логин>`**, вход через GitHub.
Домен проверять не надо: домен нам нужен был бы только для имени вида
`com.наш-домен/...`, а его у нас нет.

**Одна настоящая мина.** Реестр не разрешает двум разным серверам иметь
**в точности один и тот же** адрес. Голый `https://mcp.apify.com/` уже занят —
его держит сам Apify под именем `com.apify/apify-mcp-server`. Наши адреса
другие, у них есть хвост `?actors=...`, поэтому конфликта нет. **Но это значит,
что убирать хвост из адреса нельзя ни при каких обстоятельствах** — без него
публикация просто откажет.

смерти из начала файла. Без напоминания оно не сработает.
